# lotto-opt v0.2

로또 6/45 번호 포트폴리오(30세트, 50세트 등)를 설정 파일의 규칙대로 짜 주는 최적화 프로그램입니다 (OR-Tools CP-SAT).

> 모든 조합의 1등 확률은 1/8,145,060으로 같습니다. 이 프로그램은 당첨 확률을 바꾸지 않고, 포트폴리오의 구조(목표 분포에 맞추기, 세트끼리 덜 겹치기, 번호를 고르게 쓰기)만 최적화합니다.

## 실행
```
python3 -m pip install -r requirements.txt
python3 cli.py run --config config/to_be.yaml                # 개선안 30세트 (실행할 때마다 새 조합)
python3 cli.py run --config config/to_be.yaml --sets 50      # 50세트 (기획서의 50세트 기준 자동 적용)
python3 cli.py run --config config/to_be.yaml --seed 7       # 시드를 정하면 언제 돌려도 같은 결과
python3 cli.py run --config config/as_is.yaml                # 원본 기획서 규칙
python3 cli.py compare --config config/as_is.yaml --config config/to_be.yaml --sets 50   # 같은 데이터·같은 시드로 비교
python3 cli.py run --config config/to_be.yaml --effort 2     # 탐색량 두 배 (보통 1이면 충분)
python3 cli.py run --config config/to_be.yaml --set targets.odd_even=spec   # 설정 파일을 고치지 않고 항목 바꾸기
```
- 당첨 확인: `python3 cli.py check out/to_be_30sets_seed7.json` (데이터의 최신 회차와 비교), `--draw 1244`(회차 지정), `--numbers 1,2,3,4,5,6 --bonus 7`(직접 입력), `--json`(프로그램에서 읽을 JSON). 세트별 일치 번호와 등수(1등 6개, 2등 5개+보너스, 3등 5개, 4등 4개, 5등 3개), 등수별 개수, 최고 등수를 보여 줍니다.
- 결과는 `out/<프리셋>_<세트수>sets_seed<시드>.md`(리포트)와 `.json` 에 저장됩니다. 리포트 맨 위에 같은 결과를 다시 만드는 명령이 적혀 있습니다.
- 종료 코드 1은 독립 검증에서 규칙 위반이 나왔다는 뜻입니다.
- 당첨번호는 동행복권 공식 API → 공개 미러 → `data/draws.json` 캐시 순서로 가져옵니다. 최신 회차를 받지 못하면 캐시를 쓰고 리포트에 그렇게 적습니다 (`--source`, `--data`).

그 밖에 바뀐 점
- 세트 구성 목표를 Hot/Warm/Cold 개수 따로가 아니라 (Hot, Warm, Cold) 조합 단위로 맞춥니다. 따로 맞추면 서로 모순되는 목표가 생겼습니다.
- 합계 목표: 최근 100회 합계를 5구간으로 나눠 실제 비율대로 맞춥니다 (v0.1의 낮은 합계 쏠림 해소).
- 30·50세트는 기획서 기준(출현 횟수, 이월수 사용 횟수, 커버리지, 평균회귀)을 자동 적용하고, 다른 세트 수는 가까운 기준을 비례 조정합니다 (`profiles`).
- 리포트에 목표 대비 실제 표, 단계별 결과, 실행 시간, 재현 명령을 넣었습니다.

## 푸는 방식
1. 규칙을 모두 지키는 출발 포트폴리오를 시드로 정해지는 난수로 만듭니다 (`pool.py`).
2. 목표를 우선순위대로 하나씩 줄입니다: 분포 오차 → 세트 간 겹침 → 번호 사용 편차. 앞 단계 결과는 다음 단계에서 나빠지지 않게 고정합니다.
3. 단계마다 번호 하나 바꾸기·맞바꾸기 같은 작은 수정을 빠르게 수만 번 시도하고(`search.py`), 세트 몇 개만 풀어 둔 작은 CP-SAT 문제 여러 개를 동시에 풀어 좋아진 결과를 합칩니다(`solver.py`).
4. 분포 오차는 이론상 최소치(하한)를 미리 계산해 두고, 거기 닿으면 "최적"으로 표시하고 다음 단계로 넘어갑니다.
5. 모든 풀이가 시드와 '결정적 시간'으로 움직여서 같은 시드면 컴퓨터 속도와 상관없이 같은 결과가 나옵니다. OR-Tools 버전이 바뀌면 결과도 달라질 수 있어 `requirements.txt` 에 버전을 고정했습니다.

## 구조
| 파일 | 역할 |
|---|---|
| `lotto_opt/data.py` | 동행복권 공식 API → 공개 미러 → 캐시, 회차 누락·번호 검증, 최신 회차 계산(한국 시간) |
| `lotto_opt/stats.py` | 가중 빈도, Hot/Warm/Cold, 최장 미출현, 목표 분포 산출(`auto`/`spec`/직접 지정) |
| `lotto_opt/config.py` | 설정 읽기, `--set` 덮어쓰기, 세트 수별 기준(`profiles`) 적용 |
| `lotto_opt/constraints/set_level.py` | 세트 제약: 그룹 조합, 이월수, 합계·합계 구간, 연속수, AC, 구간, 홀짝/저고 개수 |
| `lotto_opt/constraints/global_level.py` | 전역 제약: 출현 횟수, 커버리지, 평균회귀 강제, 연속수 0쌍 비율, 분포 밴드, 교집합 |
| `lotto_opt/objective.py` | 사전식 단계: 분포 오차 → 교집합 → 출현 분산 (CP-SAT 식, 같은 값의 파이썬 계산, 하한) |
| `lotto_opt/pool.py` | 유효 세트 후보 풀과 출발 포트폴리오 |
| `lotto_opt/check.py` | 당첨 확인: 세트별 일치 번호·등수, 등수별 요약 |
| `lotto_opt/search.py` | 빠른 지역 탐색 (번호 바꾸기·맞바꾸기) |
| `lotto_opt/solver.py` | 단계별 이웃 탐색(LNS), `relax` 목록 자동 완화 |
| `lotto_opt/validate.py` | 솔버와 독립된 순수 파이썬 재검사 |
| `lotto_opt/report.py` | 리포트(.md), JSON, 프리셋 비교표 |

## 설정
모든 규칙은 `config/*.yaml` 에 있습니다.
- `targets`: `auto`(최근 100회 실측), `spec`(기획서 값), 숫자 분포(직접 지정), `null`(목표 없음). 홀짝, 저고, 세트당 이월수 개수, 세트 구성(Hot-Warm-Cold 조합), 합계 구간.
- `profiles`: 세트 수별 기준. 30, 50은 기획서 값입니다.
- `objective`: 단계 순서와 탐색량(`rounds` 최대 라운드, `patience` 개선 없이 버틸 라운드).
- `relax`: 해가 없을 때 순서대로 적용할 완화.

홀짝 목표의 기본은 최근 100회 실측값입니다. 기획서 값(4:2 36%, 3:3 33%, 2:4 24%, 기타 7%)을 쓰려면 `--set targets.odd_even=spec` 으로 실행하세요.

## 메모
- 50세트에서는 이월수를 각 7~10회 쓰라는 기준 때문에, 이월수 목표 분포(최근 100회 실측 0개 37%, 1개 47%, 2개 16%)보다 이월수 든 세트가 많아질 수밖에 없습니다. 하한 계산에 이 점을 넣어 두어서, 리포트의 "최적"은 이 기준까지 감안한 최소치입니다.
- 세트 정렬식 대칭 제거는 탐색을 크게 늦춰서 기본으로 꺼 두었습니다 (`rules.symmetry_breaking`).
- `group_mix: auto` 는 지금 정한 Hot/Warm/Cold 그룹을 그 그룹을 정한 같은 100회에 대입해 잰 비율이라 Hot 비중이 높게 나옵니다 (회차당 Hot 평균: 표본 안 2.31개, 매 회차 직전 100회로 그룹을 정해 다음 회차에 대 보면 1.83개, 무작위 기대치 1.87개). 다음 버전 후보입니다.
